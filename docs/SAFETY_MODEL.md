# 安全模型

这个项目控制的是带有私有 HID 接口的键盘。错误报文可能改变板载配置、导致不可预期的键位行为，或破坏用户无法导出的屏幕内容。

因此项目采用以下边界：

1. **白名单写入**：只有已有实机证据的序列可以写入。屏幕时钟为已验证；基础灯效、自定义单键灯光、系统设置、改键、宏和实时灯效为实验性。实时灯效与音乐律动只由电脑逐帧推送显示，不写入键盘的保存设置，停止即恢复。
2. **不枚举 opcode**：不会为寻找功能而向设备穷举未知命令。实机试验只发送从 Windows 驱动静态分析中逐字节还原的序列。
3. **先恢复能力，后开放功能**：涉及配置的功能必须先有读取或明确的可恢复路径。基础灯效没有读回命令，靠键盘自带的 `Fn+\|`、`Fn+↑/↓`、`Fn+-/=` 恢复；自定义单键颜色可以读回，写入前读取已保存的颜色并合并，写后读回核对；系统设置没有读回命令，但六项都可以重写，不带参数写入即回到驱动默认值；改键没有读回命令，恢复路径是写回全默认的两层（`ak35i keymap reset --apply`，与驱动“重置键盘”发送的内容相同），改错时可用 Mac 自带键盘执行；宏无法读回，恢复路径是上传空宏表（`ak35i macro clear --apply`，与驱动在没有宏时发送的内容相同）并恢复改键；屏幕同样无法读回，实机试验前须先写明恢复路径并征得用户同意（屏幕的出厂开机动画无法恢复）。
4. **实验性写入需要显式确认和设备应答**：只在控制中心页面的确认弹窗或 CLI 加 `--apply` 之后才写入；与 Windows 驱动相同，会话开始、设置命令和保存命令之后都读回键盘确认。会话开始命令未确认时立即停止，不发送任何设置数据；之后的命令未确认时，按驱动顺序结束会话并报告失败。
5. **不处理固件**：固件升级、DFU、恢复出厂永远不在范围内。
6. **USB 优先**：蓝牙与 2.4G 的配置行为没有得到验证时，界面会明确显示不支持。
7. **最小数据**：不上传数据，不保存设备序列号，不包含厂商二进制资源。

这意味着部分页面会显示“等待抓包”而不是提供看似可用的按钮。该设计优先保护设备状态与用户数据。
